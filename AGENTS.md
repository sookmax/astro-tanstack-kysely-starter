# AGENTS.md

Guidance for coding agents working in this repo. [README.md](README.md) covers setup and the stack; [ARCHITECTURE.md](ARCHITECTURE.md) explains _why_ things are wired the way they are — read it before changing data loading, the router bridge, auth or the DB. This file is the short version: the rules that break things when ignored, and where a change goes.

## Commands

Node 24, pnpm (never npm/yarn), Docker for Postgres.

```bash
pnpm db:up && pnpm db:migrate   # Postgres on :54320, migrate + seed + codegen (needs .env)
pnpm dev                        # http://localhost:4321
pnpm lint                       # oxlint (type-aware, reports type errors) + astro check — run before finishing
pnpm test                       # Vitest units
pnpm test:e2e:dev               # Playwright against the running dev server (fast loop)
pnpm test:e2e                   # Playwright against the production Docker image (what CI-grade means here)
pnpm format                     # Prettier
```

The pre-commit hook runs `pnpm lint`. There is no separate `tsc` step: oxlint does type checking for `.ts`/`.tsx`, `astro check` for `.astro`.

## Rules that matter

**Client/server boundary**

- `src/lib/queries/*` and anything else that imports `db`/`pg` or reads secrets is server-only and starts with `import "@/utils/server-module"`.
- Client code (routes, components, hooks, `lib/fetch`) imports schemas and types from `src/lib/schemas/*.schema.ts` only. Those files must never import anything that reaches `db`.
- Limits shared by a DB `CHECK` and a Zod schema live in `src/constants.ts`, which imports nothing.
- Read env via `process.env` on the server, never `import.meta.env` (Vite inlines it into the bundle).

**Data loading (TanStack Query)**

- Every query key comes from `queryKeys` in `src/lib/query-common.ts`. Server options (`query-server.ts`, `queryFn` → DB) and client options (`query-client.ts`, `queryFn` → `fetch` API) must use the same key, or SSR data won't be reused on the client.
- Use `query()` / `infiniteQuery()` only. Do not use `fetchQuery`, `prefetchQuery`, `ensureQueryData` or their infinite twins (deprecated) — see the mapping table in ARCHITECTURE.md.
- `query()` rejects; fire-and-forget calls need `.catch(noop)`. Keep observer-only options (`refetchOnWindowFocus`, `placeholderData`, …) out of shared options.

**Auth and identity**

- API routes take identity from `locals.user`, never the request. When merging with URL/body params, spread identity **last** so it can't be overridden.
- Auth-only pages gate in three places: the `.astro` page (redirect on direct hit), the route's `beforeLoad` (redirect on client nav), and the API (401).

**Database**

- Migrations are the source of truth. `src/db/schema.ts` is generated — never edit it; run `pnpm db:migrate` (or `pnpm db:codegen`) to regenerate.
- Never edit a migration that may have run anywhere shared; add a new one named with `pnpm db:timestamp`.
- Match DB errors by `code` + constraint name (`src/db/utils/errorCode.ts`), never by message.
- Seeds are data migrations in `src/db/seed/`, tagged with `seed_id`.

**Errors**

- API routes return `SomeError.response()` (from `src/utils/error.ts`) and wrap DB calls with `handleApiError`. Fetch wrappers `throw await AppError.fromResponse(res)`. Don't surface raw error messages to users.

**Generated files** — don't hand-edit: `src/db/schema.ts`, `src/react/routeTree.gen.ts` (regenerated by the router plugin during `pnpm dev`/`build`, or `pnpm generate-routes`).

## Where a change goes

Adding a page with data, end to end (follow the guestbook's `entries` feature as the template):

1. **Schema** — Zod schema + types in `src/lib/schemas/<name>.schema.ts` (client-safe). Add a co-located `.test.ts` if it has logic.
2. **DB** (if needed) — table module in `src/db/schemas/`, a new migration in `src/db/migrations/` composing it, then `pnpm db:migrate`.
3. **Server query** — `src/lib/queries/<name>.ts` (server-only guard).
4. **API route** — `src/pages/api/...`: validate with `safeParse`, identity from `locals`, errors via `AppError`.
5. **Fetch wrapper** — `src/lib/fetch/`.
6. **Query options** — key in `query-common.ts`, server options in `query-server.ts`, client options in `query-client.ts`.
7. **Astro page** — `src/pages/<path>.astro` fills the cache in frontmatter and renders `ReactServerEntry`.
8. **Route** — `src/react/routes/<path>.tsx` with a `beforeLoad` using the client options; components in `src/react/components/` (add a story for presentational ones).
9. **Tests** — API contract in `e2e/api/`, user flow in `e2e/browser/` (use the `authedPage` fixture; each test signs up its own user, so no shared state).

Mutations: invalidate the `queryKeys.entries`-style prefix for create/delete; for optimistic updates follow `src/react/hooks/useEntryMutations.ts` (patch, roll back on error, reconcile on success).

## Style

- Prettier formats; oxlint lints. Use the `@/` import alias.
- Styling is Tailwind 4 with the semantic `light-dark()` tokens in `src/styles/global.css` — use those tokens rather than raw colors. Merge classes with `cn()` (`src/utils/cn.ts`).
- Comments explain _why_ (non-obvious constraints, gotchas), matching the existing code; skip ones that restate the code.

## Verifying UI changes

`.claude/launch.json` defines `dev` (:4321) and `storybook` (:6006). The app shows a loading overlay until hydration; e2e helpers wait for it to disappear (`e2e/browser/helpers/hydration.ts`) — do the same when driving the page manually.
